# 참고문헌 검증 서비스 (refcheck.kr)

원고 파일(HWP·HWPX·DOCX·PDF·TXT)을 업로드하면 참고문헌을 자동 추출해
선택한 학술지 기준으로 정리·검증해 주는 로컬 웹 애플리케이션입니다.

- 기본 기준: 문편협 「인용 및 참고문헌의 기술요소와 형식에 관한 공통기준」(2024. 6. 17. 개정)
- 사용자 기준: 학술지 투고규정을 파일·URL·직접 입력으로 추가하면 그 기준에 맞춰 변환(AI 모드)

## 실행 방법

1. (최초 1회) 의존성 설치
   ```
   pip install -r requirements.txt
   ```
2. `실행.bat` 더블클릭 → 브라우저에서 http://localhost:8765 자동 열림

## 주요 기능

| 기능 | 설명 |
|---|---|
| 단건 검증(옴니박스) | DOI·ISBN·URL·제목 한 줄을 자동 판별해 참고문헌 1건을 즉석 표준화·검증(`/api/quick`) — 접근 코드 없이 사용 가능, AI 미사용(비용 0원), IP당 분당 12회 제한 |
| 참고문헌 자동 추출 | 원고에서 참고문헌 구역을 탐지하고 문헌을 건별 분리 |
| 기준 선택·추가 | 문편협 기본 + 학술지별 기준을 파일/링크/직접 입력으로 등록 |
| 형식 변환·정렬 | 유형별 기술형식, 저자 표기, 대소문자, 국내→서양→동양 배열, 동일 저자·연도 a,b,c 부기 |
| 형식 검증 | 누락 서지요소를 '확인 필요'로 표시 |
| 실존 검증 | Crossref → OpenAlex → Semantic Scholar 폴백 체인 + DataCite. 다중 DB 미발견 시 'AI 생성 인용 의심' 표시, DOI 자동 보정 |
| 철회 논문 검출 | 인용 문헌의 철회(Retraction)·정정·우려표명 여부 검사(Crossref·Retraction Watch 데이터) |
| 국내 문헌 검증 | KCI(학술지 논문)·국회도서관(학위논문)·국립중앙도서관(단행본) 대조 — .env에 무료 API 키 설정 시 활성화 |
| 서지 자동 교정 | 매칭된 공식 서지와 다른 연도·권·호·면수를 수정 제안(옵션 켜면 자동 반영) |
| 미매칭 재조회 | 제목 검색이 놓친 항목(미확인·불일치·의심)에 DOI·ISBN을 직접 입력해 그 항목만 재검증 — 결과와 처리 이력에 함께 반영 |
| 근거 레코드 링크 | 판정 배지 옆 'KCI 레코드·DOI 원문·국립중앙도서관' 링크로 원본 레코드 직접 확인 |
| 학술지 신뢰성 | KCI 등재·DOAJ 등재 여부 대조, 프리프린트 인용 → 정식 출판본 교체 제안 |
| 건전성 리포트 | 연도 분포·최근 10년 비율·중복 문헌·자기인용·저널 편중 집계 |
| 본문-목록 대조 | 본문에 인용됐는데 목록에 없는 문헌 / 목록에만 있는 문헌 검출 |
| 내보내기 | DOCX(링크 클릭 가능)·**한글 HWPX(내어쓰기 적용)**·TXT·RIS(EndNote/Zotero)·BibTeX·ZIP |
| 검사 확인서 | DOCX 1쪽에 투고 첨부용 요약 확인서(검사일·판정 집계·정보원·버전) — KCI 유사도 검사 결과서의 참고문헌판 |
| 작성법 가이드 | `/guide/style` 공개 페이지 — 문편협 공통기준 자료 유형별 표기 예시(엔진 출력과 동일) |
| 학회 전환 미리보기 | 결과 화면에서 다른 학회지 선택 시 그 학회에서 확인된 편집 관행을 현재 목록에 겹쳐 표시(`/api/org_preview`) |
| 영문 변환 목록 | 국문 참고문헌의 영문 목록 자동 생성(문편협 9·10항, AI 모드) |
| 폴더 일괄 처리 | 폴더 내 원고를 한 번에 처리, 파일별 DOCX + 종합리포트 저장 |
| 결과 산출 | 변경 전·후 대비표, 최종 목록, DOCX/TXT/ZIP 다운로드 |
| 검증 정보원 안내 | 기준 선택·결과 화면의 '🔎 검증 정보원'에서 국내(KCI·국립중앙도서관·국회도서관)·해외(Crossref·OpenAlex·Semantic Scholar·DataCite·DOAJ·URL) 정보원과 연결 상태를 이용자도 확인 |
| 작성 제안 표시 | 문편협 기준이 애매한 부분에 '논문 사례를 통한 제안'·'발행본 검토 제안'을 항목별 참고 정보로 표시(결과 화면·DOCX·TXT) |
| 관리자 추가 기준 | 문편협에 준하는 추가 기준을 등록하면 변환에 반영 — 문편협 명시 규정과 충돌 시 문편협 우선·경고 표시(AI 모드) |
| 사례 논문 분석 | 학회지 발행 논문을 업로드하면 AI가 참고문헌 관행 패턴을 분석해 '논문 사례를 통한 제안' 초안으로 축적(관리자 검토 후 사용) |
| 발행본 비교 | 에이전트 처리 이력과 학회지 최종 발행본의 참고문헌을 항목별로 대조 — 차이를 체크·채택하면 '발행본 검토 제안'으로 등록 |

## 관리자 모드 / 이용자 모드

- **이용자 모드(기본)**: 기준 선택, 원고 처리(업로드·폴더 일괄), 결과 다운로드만 가능.
  화면에는 현재 엔진 모드(AI/규칙 기반) 배지만 표시되고 API 키 정보는 보이지 않습니다.
  처리 시작 전에 **이름과 사용 기관(학회)**을 입력해야 하며(기본 4개 학회 + 기타 직접 입력),
  입력 내용은 사용 통계로 기록됩니다(`app/usage_log.json`).
- **관리자 모드**: 화면 오른쪽 위 **🔐 관리자**로 로그인하면 ⚙ 설정(API 키·모델),
  참고문헌 기준 추가·삭제, **📊 사용 통계**(기관별 사용 횟수·파일·문헌 집계, 최근 사용 내역),
  **📋 기준·제안 관리**가 활성화됩니다. 로그인 유지 시간은 12시간입니다.

### 기준·제안 관리 (관리자) — 기준의 4층 체계

적용 우선순위는 다음과 같으며, 문편협 공통 기준이 항상 일순위입니다.

1. **문편협 공통 기준** — 항상 적용(내장).
2. **관리자 추가 기준**(`app/admin_standards.json`) — 문편협에 준하는 기준. 변환에 실제
   반영되며, 문편협 명시 규정과 충돌하면 적용하지 않고 처리 결과에 경고로 알립니다.
3. **논문 사례를 통한 제안**(`app/suggestions.json`의 case) — 4개 학회지 2025년 이후 발행
   논문의 실제 관행에서 추출. 변환 결과를 바꾸지 않고 이용자에게 참고 정보로만 표시됩니다.
   '사례 논문 등록'으로 발행 논문을 업로드하면 AI가 새 패턴을 초안(미사용)으로 추가하며,
   관리자가 검토 후 '사용'으로 켜야 표시됩니다.
4. **발행본 검토 제안**(`app/suggestions.json`의 prof) — '발행본 비교' 탭에서
   에이전트 처리 이력과 학회지 최종 발행본을 대조해, 관리자가 채택한 차이가 축적됩니다.
   역시 표시 전용이며 문편협 공통 기준이 아님이 명칭으로 구분됩니다.
5. **○○학회 제안**(`app/suggestions.json`의 org) — 학회 편집위원의 채택 요청을
   편집위원장이 승인해 등록된 제안. **그 학회 이용자에게만** 표시됩니다.

처리 이력은 `app/history/`에 자동 저장되어(최근 300건) 발행본 비교의 대상 목록이 됩니다.
- 관리자 계정은 프로젝트 루트 `.env` 파일에 설정합니다:
  ```
  ADMIN_ID=원하는아이디
  ADMIN_PASSWORD=원하는비밀번호
  ```
  (초기 자리표시 값 `바꿔주세요` 상태에서는 로그인이 차단됩니다 — 반드시 변경 후 사용)

## 엔진 (하이브리드)

- **규칙 기반 엔진**: API 키 없이 바로 동작. 정규식·휴리스틱으로 추출·변환.
- **AI 모드**: 설정(⚙)에서 Claude API 키를 등록하면 추출·유형 판별·변환 정확도가 크게 향상되고,
  사용자 정의 기준 적용과 영문 변환 목록 기능이 활성화됩니다.
  - 키 발급: https://console.anthropic.com
  - 키는 이 컴퓨터의 `app/config.json`에만 저장됩니다.

## 정식 운영 (외부 접속)

클라우드 서버 + 개인 도메인 + HTTPS로 외부에 공개 운영하는 방법은
**[deploy/배포가이드.md](deploy/배포가이드.md)** 를 따르세요. 외부 운영용 보안 장치가 내장되어 있습니다.

- **접근 코드·역할**: 관리자 ⚙ 설정에서 학회마다 **이용자·편집위원·편집위원장 코드**를
  각각 지정합니다(+ 학회 구분 없는 공통 코드). 입장 화면은 두 칸입니다 —
  일반 이용자는 **학회 코드**만, 편집위원·편집위원장은 **학회 코드 + 역할 코드**를 함께
  입력합니다. 역할 코드는 자기 학회 코드와 짝을 이룰 때만 유효합니다(다른 학회 코드와
  조합하면 거부). 코드를 모두 비워 두면 제한 없음(로컬 기본).
  `.env`의 `ACCESS_CODE`는 공통 코드의 폴백입니다.

  | 역할 | 권한 |
  |---|---|
  | 이용자 | 원고 처리, 자기 학회의 지난 결과 열람·재다운로드 |
  | 편집위원 | + 자기 학회 사용 통계, 원고·결과 관리(다운로드), 발행본 3단 비교·CSV, 규칙 **채택 요청** |
  | 편집위원장 | + 자기 학회 자료 삭제, 채택 요청 **승인·반려** |
  | 관리자 | 전체 학회, 기준·제안 관리, 규칙 채택, 설정 |

  **채택 요청 워크플로**: 편집위원이 발행본 비교에서 찾은 차이를 [채택 요청] →
  편집위원장(또는 관리자)이 승인 → **'○○학회 제안'**으로 등록되어 그 학회 이용자의
  처리 결과에만 표시됩니다. 관리자는 언제든 끄거나 삭제할 수 있습니다.
- **폴더 일괄 처리**: 서버 로컬 폴더를 읽는 기능이므로 관리자 전용입니다.
- **HTTPS 쿠키 보호**: 서버 `.env`에서 `COOKIE_SECURE=1` 설정.
- **API 비용 안전장치**: console.anthropic.com → Billing에서 월 사용 한도 설정을 권장합니다.

## 유의사항

- 자동 변환 결과는 투고 전 반드시 변경 전·후 대비표로 최종 확인하세요.
- 스캔본 PDF는 OCR 후 사용하세요. 구형 HWP(5.0)는 그대로 읽지만, 암호·배포용으로 잠긴 파일은 HWPX/PDF로 저장한 뒤 올려야 합니다.
- 국내 문헌의 실존 검증은 Crossref 등록 여부에 따라 제한될 수 있습니다(KCI·RISS에서 확인 권장).
