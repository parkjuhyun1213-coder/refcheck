# 정식 운영 배포 가이드 — 참고문헌 표준화·검증 에이전트

이 문서는 참고문헌 에이전트를 **가비아 클라우드 서버 + 가비아 도메인 + HTTPS**로
정식 운영하기 위한 단계별 안내입니다. 개발 지식이 없어도 순서대로 따라 하면 됩니다.

> 참고: 가비아의 서버 상품은 2025년 5월 'g클라우드'에서 **'가비아 클라우드(Gen2)'** 로
> 개편되었습니다. 신규 가입자는 Gen2만 신청할 수 있으며 이 가이드는 Gen2 기준입니다.

## 1단계. 가비아 클라우드 가입·서버 만들기 (약 15분)

1. https://www.gabiacloud.com 접속 → 가비아 회원으로 로그인(없으면 가입) →
   **가비아 클라우드 Gen2 신청**. 신청 시 **그룹 이름·콘솔 주소·클라우드 계정**을 만들고
   휴대폰 인증 후 결제 수단을 등록합니다.
2. **관리콘솔**(console.gabiacloud.com) 로그인 → 프로젝트 선택 → **[컴퓨팅] → [서버]** →
   **[서버 생성하기]**:
   - 이미지: **[운영체제(OS)] → Ubuntu** (제공되는 최신 LTS 버전, 예: 22.04)
   - 서버 타입: **Micro** → 1vCore/1GB(시작용) 또는 1vCore/2GB(여유형), 루트 스토리지 50GB
   - 로그인 방식: **[비밀번호로 접속]** 선택 ← 초보자에게 가장 간단합니다.
     생성 완료 후 **root 임시 비밀번호가 이메일로 발송**됩니다(분실 시 서버 상세 페이지에서 재발급).
   - 네트워크: 서브넷 기본값(Default-Subnet) → **공인 IP [할당] → [공인 IP 생성하기]**
     → 보안 그룹 기본값(Default-SecurityGroup)
   - 이름(예: refstd) 입력 → 비용 확인 → **[생성하기]**
3. 생성 후 서버 목록에서 **공인 IP 주소를 메모**하세요 (예: 211.xx.xx.xx).

## 2단계. 방화벽(보안 그룹) 포트 열기 (약 5분)

외부 접속에 필요한 포트 3개(SSH 22, HTTP 80, HTTPS 443)가 열려 있어야 합니다.

1. 콘솔 → **[네트워크] → [보안 그룹]** → `Default-SecurityGroup` 클릭 → **[보안 규칙]** 탭
   → **[변경하기]**.
2. 인바운드 규칙에 아래 3개가 없으면 추가하고 저장:
   - TCP, 포트 **22**, 소스 `0.0.0.0/0`
   - TCP, 포트 **80**, 소스 `0.0.0.0/0`
   - TCP, 포트 **443**, 소스 `0.0.0.0/0`

## 3단계. 도메인 구입·연결 (약 10분 + DNS 전파 대기)

1. 가비아(gabia.com)에서 원하는 도메인 구입 (예: `refcheck.kr`).
2. My가비아 → **[서비스 관리] → [DNS 관리툴]** (또는 dns.gabia.com) → 도메인 선택 →
   **[DNS 설정] → [+ 레코드 추가]**:
   - 타입 **A**, 호스트 **@**, 값 = **1단계의 공인 IP**, TTL 기본값
   - (선택) 타입 **A**, 호스트 **www**, 값 = 같은 IP
3. 저장 후 전파까지 보통 몇 분~몇 시간 걸립니다.

## 4단계. 프로젝트 파일 업로드 (약 15분)

Windows에서 **WinSCP**(https://winscp.net, 무료)를 설치해 사용합니다.

1. WinSCP 실행 → 새 세션:
   - 파일 프로토콜: **SFTP** / 호스트 이름: **공인 IP** / 포트: 22
   - 사용자 이름: **root** / 비밀번호: **이메일로 받은 임시 비밀번호**
2. 접속되면 오른쪽(서버) 화면이 `/root` 입니다.
3. 왼쪽(내 컴퓨터)에서 `F:\UseAI\writing_reference_agent` 폴더 **전체**를
   오른쪽 `/root` 로 끌어다 놓습니다. → `/root/writing_reference_agent` 가 생깁니다.
   - `참고문헌_정리결과` 같은 결과물 폴더나 샘플은 빼도 됩니다(필수 아님).

## 5단계. 서버용 .env 설정 (약 5분)

서버에서는 반드시 아래 값을 바꿔야 합니다. WinSCP에서
`/root/writing_reference_agent/.env` 를 **더블클릭해 편집**하고 저장하세요.

```
ADMIN_PASSWORD=강력한비밀번호      ← 이미 강력한 값으로 설정되어 있는지 확인
ACCESS_CODE=학회지에안내할코드     ← 반드시 설정! (예: BIBLIO-2026 처럼 원하는 코드)
COOKIE_SECURE=1                   ← 서버에서는 반드시 1
ANTHROPIC_API_KEY=sk-ant-…        ← 값이 있는지 확인 (AI 모드 동작에 필요)
```

- `ACCESS_CODE`는 4개 학회지 편집위원회에만 안내하는 공용 코드입니다.
  나중에 관리자 화면 **⚙ 설정**에서 언제든 바꿀 수 있습니다.
- 로컬 컴퓨터의 `.env`는 그대로 두면 됩니다(로컬은 접근 코드 없이 사용).

## 6단계. 설치 스크립트 실행 (약 5분)

1. 가비아 콘솔의 서버 상세 페이지에서 **[터미널 접속]** 버튼을 누르면
   브라우저에서 검은 터미널 창이 열립니다(root로 로그인).
2. 아래 두 줄을 순서대로 입력(복사 → 터미널에 붙여넣기):

```bash
sed -i 's/\r$//' ~/writing_reference_agent/deploy/setup_server.sh
bash ~/writing_reference_agent/deploy/setup_server.sh 여기에도메인
```

예: `bash ~/writing_reference_agent/deploy/setup_server.sh refcheck.kr`

스크립트가 자동으로: 필요한 프로그램 설치 → 스왑 메모리 설정 → 앱을 `/opt/refstd`에 설치 →
부팅 시 자동 시작 등록 → HTTPS 인증서 자동 발급(Caddy)까지 처리합니다.

3. 끝나면 root 비밀번호도 바꿔 두세요: 터미널에 `passwd` 입력 → 새 비밀번호 두 번 입력.

## 앱 수정본 반영 — SSH 방식 (WinSCP·콘솔 터미널 없이)

윈도우 10·11에는 `ssh`·`scp`가 기본으로 들어 있습니다. **PowerShell** 창 하나에서 끝납니다.
서버 주소는 공인 IP(예: `1.201.120.29`)를 씁니다.

### 한 번만: 비밀번호 없이 접속되게 열쇠 등록

```powershell
ssh-keygen -t ed25519 -C "refcheck-deploy"        # 이미 만들어 뒀으면 건너뜀 (물음에 전부 Enter)
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@1.201.120.29 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

마지막 줄에서 한 번만 root 비밀번호를 묻습니다. 이후로는 묻지 않습니다.

### 매번: 올리고 반영하기

```powershell
cd F:\UseAI\writing_reference_agent
$S = "root@1.201.120.29"

ssh $S "mkdir -p /root/writing_reference_agent/app/static /root/writing_reference_agent/deploy"
scp app\*.py            ${S}:/root/writing_reference_agent/app/
scp app\static\*.html   ${S}:/root/writing_reference_agent/app/static/
scp deploy\*            ${S}:/root/writing_reference_agent/deploy/
scp requirements.txt    ${S}:/root/writing_reference_agent/
ssh $S "bash /root/writing_reference_agent/deploy/update.sh"
```

마지막 줄이 `update.sh`를 돌려 `/opt/refstd`에 반영하고 서비스를 재시작합니다.
"정상 실행 중 — 버전: …"이 나오면 끝입니다. 브라우저에서 **Ctrl+F5**.

- 올리는 것은 **코드뿐**입니다. `.env`·`config.json`·처리 이력 같은 운영 데이터는 서버 것이 그대로 남습니다.
- `규정/`·`샘플원고/`·`안내문/`·`.git/`은 서버에 필요 없어 올리지 않습니다.

### 확인용 명령

```powershell
ssh $S "systemctl status refstd --no-pager | head -12"          # 살아 있는지
ssh $S "journalctl -u refstd -n 40 --no-pager"                  # 오류 로그
ssh $S "/opt/refstd/venv/bin/pip list | grep -i hwp"            # 라이브러리 설치 확인
```

`update.sh`의 pip 설치 줄은 실패해도 조용히 넘어가므로(`|| true`),
requirements.txt에 새 라이브러리를 추가한 날은 세 번째 명령으로 확인하는 편이 안전합니다.

## KCI Open API 연결 (무료, 권장)

국내 학술지 논문의 실존·서지 대조와 **발행본 참고문헌 조회**가 활성화됩니다.
이것만 연결해도 국내 문헌 검증 정확도가 크게 올라갑니다.

1. https://www.kci.go.kr 접속 → 로그인(회원가입 무료)
2. 하단 또는 상단 메뉴에서 **오픈API(Open API)** 안내 페이지로 이동 → **활용 신청**
   - 신청 시 활용 목적에는 "학술지 참고문헌 검증 서비스" 같은 내용을 적으면 됩니다.
   - 승인되면 **인증키(key)** 가 발급됩니다(보통 즉시~며칠).
3. 발급받은 키를 서버 `.env`에 입력:
   - WinSCP로 `/opt/refstd/.env` 열기 → `KCI_API_KEY=발급받은키` 로 수정 → 저장
   - `.env`는 재시작 없이 즉시 반영됩니다(다음 처리부터 적용).
4. 확인: 관리자 로그인 → **⚙ 설정** 하단의 "국내 문헌 검증 API 상태"에서
   KCI가 **설정됨**으로 바뀌면 완료. 이용자 화면의 **🔎 검증 정보원**에도 "연결됨"으로 표시됩니다.

연결되면 추가로 가능한 것:
- 국내 학술지 논문의 실존·서지 대조(연도·권·호·면수 자동 교정 포함)
- 학술지 KCI 등재 여부 확인
- **발행본 비교 탭에서 파일 없이** 논문명만으로 KCI에 실린 참고문헌을 가져와 3단 비교

## 자동 백업 (GitHub 비공개 저장소, 무료)

서버가 매일 새벽 4시에 두 갈래로 백업합니다.

- **GitHub 비공개 저장소**: 처리 이력·사용자 기준·제안·통계·비교 코퍼스.
  **원고 원본(uploads/)은 올리지 않습니다** — 학회에 '보관 자료는 외부에 제공하지
  않는다'고 안내했기 때문입니다. 저장소가 실수로 Public이면 스크립트가 스스로 중단합니다.
- **서버 내 로컬 미러**(`/opt/refstd-local-backup`): 원고·발행본 파일. 실수 삭제 대비용이며
  서버 디스크 장애 시에는 원고를 복구할 수 없다는 한계를 감수하는 정책입니다.

`.env`·`config.json`(비밀키)은 어디에도 백업되지 않습니다.

**최초 1회 설치:**

1. GitHub에서 새 저장소 생성: 이름 `refcheck-backup`, **반드시 Private 선택**, README 추가 안 함.
2. 서버 SSH 접속 후 백업용 열쇠 생성·출력:
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/backup_key -N "" -q && cat ~/.ssh/backup_key.pub
   ```
   출력된 `ssh-ed25519 AAAA…` 한 줄을 복사.
3. GitHub의 refcheck-backup 저장소 → Settings → **Deploy keys** → Add deploy key:
   제목 아무거나, Key에 붙여넣기, **✔ Allow write access 체크** → Add.
4. 서버에서 (한 줄씩):
   ```bash
   git config --global user.name "refcheck-server"
   git config --global user.email "backup@refcheck.kr"
   GIT_SSH_COMMAND="ssh -i ~/.ssh/backup_key -o StrictHostKeyChecking=accept-new" git clone git@github.com:깃허브아이디/refcheck-backup.git /opt/refstd-backup
   cd /opt/refstd-backup && git config core.sshCommand "ssh -i ~/.ssh/backup_key -o StrictHostKeyChecking=accept-new"
   sed -i 's/\r$//' /opt/refstd/deploy/backup_github.sh
   bash /opt/refstd/deploy/backup_github.sh   # 첫 백업 실행·확인
   (crontab -l 2>/dev/null; echo "0 4 * * * bash /opt/refstd/deploy/backup_github.sh >> /var/log/refstd-backup.log 2>&1") | crontab -
   ```
5. GitHub 저장소 페이지를 새로고침해 `data/` 폴더가 생겼는지 확인하면 끝.
   이후 복구가 필요하면 이 저장소의 data/ 내용을 서버 `/opt/refstd/app/`에 되돌려 넣으면 됩니다.

## 문제 해결

- **사이트가 안 열림** → DNS 전파 대기(최대 수 시간) / 2단계 보안 그룹에 80·443을 추가했는지 확인.
- **"연결이 비공개가 아닙니다" 오류** → 도메인 DNS가 서버 IP를 가리킨 뒤 Caddy가 인증서를
  자동 발급하기까지 1~2분 걸립니다. `systemctl restart caddy` 후 재시도.
- **502 오류** → 앱이 꺼진 상태. `systemctl restart refstd` 후
  `journalctl -u refstd -n 50` 으로 오류 확인.
- **AI 모드가 꺼져 있음** → 서버 `.env`의 `ANTHROPIC_API_KEY` 확인 또는
  ⚙ 설정에서 키 입력 → 키 검증.
- **처리 중 서버가 느려짐/멈춤** → 1GB 사양의 한계일 수 있습니다. 가비아 콘솔에서
  2GB 사양으로 변경을 검토하세요.
